# HabitFlow — трекер привычек

**Название:** HabitFlow (в интерфейсе — «Трекер привычек»), Telegram-ассистент в проекте называется **Савелий**.

**Решаемая задача:** люди расстаются с полезными привычками не потому, что им не хватает мотивации, а потому что план живёт «в голове» — нет видимого прогресса, нет связи с моментом действия и нет внешнего напоминания в правильное время. HabitFlow превращает намерение в измеримый процесс: привязывает привычку к **дням недели и времени**, заранее напоминает о старте, повторяет напоминание, пока задача не отмечена, и показывает серию (streak) как главный сигнал прогресса.

---

## Кто пользователь

| Роль | Что получает |
|---|---|
| **Владелец (обычный пользователь)** | Веб-приложение: заводит привычки, отмечает выполнение, смотрит статистику, серии, достижения и советы AI-коуча. Целевая аудитория — человек, который хочет выстроить 3–10 регулярных действий (вода, спорт, чтение, медитация, язык) и регулярно «забывает» про них. |
| **Пользователь Telegram** | Не заходит в сайт: управляет всем из чата, получает напоминания в нужное время и отвечает на них кнопками. |
| **Разработчик / интеграции** | REST API v1 с API-ключом, iCalendar/CSV/JSON-выгрузки, вебхуки. |

Ассистент **Савелий** — персона, общается свободным текстом, знает фактические данные пользователя (сколько привычек на сегодня, что уже отмечено, лучший рекорд) и отвечает по системному промпту `Савелий_системный_промпт.md`.

## Основные возможности

### Веб-приложение
- Регистрация / вход, личный кабинет.
- Привычки: название, эмодзи-иконка, цвет, **дни недели**, **время действия**, **напоминать за N минут**, **дата начала**, заметка, категория, теги.
- Отметка выполнения на сегодня, серии (`🔥`), рекорды, отметка «недостатка» (imperfection) при срыве.
- **Статистика** за неделю / месяц / год: общий процент, выполнено / пропущено, разбивка по привычкам.
- **Категории**, **теги**, **достижения и бейджи**, отдельная страница `/achievements`.
- **AI-коуч** (`/coach`) — сводка и инсайты на основе реальной статистики.
- **Виджет** (`/widget`) — краткий блок прогресса для встраивания.
- **Экспорт/импорт:** CSV (`/export/csv`), JSON (`/export/json`), импорт JSON, календарь **iCalendar** (`/calendar.ics`).
- **Настройки:** часовой пояс, время общего напоминания, включение/выключение уведомлений.
- **Интеграции:** API-ключ с кнопкой копирования, привязка Telegram, тестовое сообщение, вебхук.
- **PWA:** `manifest.json`, service worker, иконки 192/512, favicon, apple-touch-icon.

### Напоминания (сервер, по времени привычки)
- Работают **в часовом поясе пользователя** (по умолчанию `Europe/Moscow`).
- Три события: **за N минут** до времени → **в сам момент** → **повторы каждые 30 минут, максимум 3 раза**, пока привычка не отмечена.
- Повторы несут стимулирующее сообщение к цели.
- Учитываются дни недели и дата начала — в «нерабочие» для привычки дни напоминаний нет.
- Привычки без времени не участвуют (бот подсказывает, как задать время).
- В напоминании есть inline-кнопки: **✅ Сделал**, **⏰ +10 мин**, **❌ Пропустить сегодня**.

### Telegram-бот «Савелий»
Управление и свободный диалог в чате. Лонг-поллинг на stdlib, без внешних SDK.

### REST API v1
Полный доступ к данным по API-ключу (`X-API-Key`).

## Стек

| Слой | Технологии |
|---|---|
| Бэкенд | Python 3.14, **Flask 3.1**, `sqlite3`, шаблоны Jinja2 |
| Хостинг | gunicorn (`Procfile`), Railway (VPS-вариант тоже подойдёт) |
| Бот | Python stdlib (`urllib`, `json`), long polling, без сторонних библиотек |
| LLM | ProxyAPI (OpenAI-совместимый формат), модель `openai/gpt-4o-mini` |
| Фронтенд | Ванильные CSS/JS, PWA (manifest + service worker) |

Зависимости — `requirements.txt`: `Flask>=3.0`, `gunicorn>=21.0`, `tzdata>=2024.1`.

## Быстрый старт (локально)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# ключ LLM (необязательно — без него бот работает, но без диалога)
# положите его в файл llm_key.txt

python app.py        # сайт: http://127.0.0.1:5000
```

Telegram-бот запускается отдельным процессом (Windows: `start.bat`):

```powershell
$env:TELEGRAM_BOT_TOKEN = "токен от @BotFather"
$env:HABITFLOW_URL = "http://127.0.0.1:5000"
python telegram_bot.py
```

> Консоль Windows с кодировкой cp1251: для корректного вывода эмодзи/кириллицы задайте `$env:PYTHONUTF8="1"`.

## Команды Telegram-бота

| Команда | Что делает |
|---|---|
| `/start`, `/help` | справка по всем командам |
| `/today` | привычки на сегодня и их отметка кнопками |
| `/habits` | список привычек **с номерами**, временем, днами, «за N мин», датой начала |
| `/add Название \| 08:30 \| Пн,Ср,Пт \| 10` | создать привычку (части после названия необязательны) |
| `/set НОМЕР time 08:30` | изменить время; `... time нет` — убрать время |
| `/set НОМЕР days Пн,Ср,Пт` | дни: `Пн,Ср,Пт`, `будни`, `выходные`, `каждый день`, `1,3,5` |
| `/set НОМЕР remind 10` | за сколько минут напомнить |
| `/set НОМЕР start 2026-11-01` | дата начала (`... start нет` — убрать) |
| `/tz Europe/Moscow` | часовой пояс пользователя |
| `/stats [week\|month\|year]` | статистика |
| `/coach` | советы AI-коуча |
| `/link <API-ключ>` | привязать аккаунт и включить напоминания |
| `/unlink` | отвязать аккаунт |
| `/chatid` | показать chat ID |
| `/diag` | диагностика связи с трекером |
| `/reset` | очистить историю диалога с Савелием |

Свободный текст (не команда) уходит в Савелия через LLM.

## REST API v1

Аутентификация — заголовок `X-API-Key` (ключ берётся на странице «Интеграции»).

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/me` | профиль: email, timezone, уведомления, статус Telegram |
| `PATCH` | `/api/v1/me` | обновить `timezone`, `notifications_enabled` |
| `GET` | `/api/v1/habits` | список привычек |
| `POST` | `/api/v1/habits` | создать (`title`, `days`, `remind_time`, `remind_before`, `start_date`, `icon`, `color`, `category_id`) |
| `GET` | `/api/v1/habits/<id>` | одна привычка |
| `PATCH` | `/api/v1/habits/<id>` | изменить |
| `DELETE` | `/api/v1/habits/<id>` | удалить |
| `POST` | `/api/v1/habits/<id>/check` | отметить/снять выполнение (`{"done": true}`) |
| `POST` | `/api/v1/habits/<id>/snooze` | отложить напоминание (`{"minutes": 10}`) |
| `POST` | `/api/v1/habits/<id>/skip` | пропустить на сегодня |
| `GET` | `/api/v1/stats?period=week\|month\|year` | статистика |
| `GET` | `/api/v1/coach` | инсайты AI-коуча |
| `POST` | `/api/v1/telegram/link` | привязать чат (`{"chat_id": ...}`) |
| `DELETE` | `/api/v1/telegram/link` | отвязать чат |
| `POST` | `/api/v1/telegram/test` | тестовое сообщение |

Веб-роуты: `/register`, `/login`, `/`, `/habits/new`, `/habits/<id>/edit`, `/habits/<id>/delete`, `/stats`, `/categories`, `/achievements`, `/coach`, `/settings`, `/integrations`, `/widget`, `/export/csv`, `/export/json`, `/import/json`, `/calendar.ics`, `/manifest.json`, `/sw.js`.

### Сервис бота (telegram-bot)

| Переменная | Назначение | Пример |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather | — |
| `HABITFLOW_URL` | адрес веб-приложения | `https://<домен>.up.railway.app` |
| `HABITFLOW_API_KEY` | ключ по умолчанию (опционально) | — |
| `HABITFLOW_LINKS` | файл привязок | `/data/bot_links.json` |

## Деплой на Railway

1. Залейте репозиторий на GitHub и создайте проект в [Railway](https://railway.com/) → **Deploy from GitHub repo** — `Procfile` поднимет веб-процесс.
2. Добавьте переменные окружения (см. таблицу выше): `SECRET_KEY`, `HABITFLOW_ENABLE_SCHEDULER=1`, `TELEGRAM_BOT_TOKEN`, `HABITFLOW_LINKS=/data/bot_links.json`, `SAVELIY_LLM_URL/KEY/MODEL`.
3. **Volume**: примонтируйте диск к сервису и укажите путь `/data` — иначе база и привязки будут теряться при пересоздании контейнера (`HABITFLOW_DB=/data/habits.db`, `HABITFLOW_LINKS=/data/bot_links.json`).
4. Из логов веб-сервиса возьмите домен `*.up.railway.app` → пропишите его в `HABITFLOW_URL` сервиса бота и перезапустите бота.
5. Второй процесс (`python telegram_bot.py`) заведите отдельным сервисом из того же репозитория (Start command: `python telegram_bot.py`).
6. Проверка: регистрация на сайте → «Интеграции» → скопировать API-ключ → в Telegram `/link <ключ>` → `/today`.

После правок кода: коммит в `main` → Railway пересобирает автоматически.

## Безопасность

- API-ключ как единственный способ доступа к `/api/v1/*`; ключи не выводятся в логи.
- Промпт и ключи LLM не раскрываются в ответах бота (правила в `SECURITY_RULES`).
- Rate-limit свободного диалога (20 сообщений / 60 с), ограничение длины ввода (2000 символов) и длины контекста знаний (6000 символов).
- URL из сообщений проверяются (`url_is_safe`: только `https` и localhost).
- История диалога ограничена и очищается командой `/reset`.
- Пароли хранятся через `werkzeug.security.generate_password_hash`.

## Ограничения и замечания

- Локальная проверка Telegram Bot API возможна не в каждой сети (заблокирован на уровне провайдера) — бот штатно работает на сервере; при блокировке используйте VPN или `HTTPS_PROXY`.
- SQLite: для одного процесса/небольшой нагрузки; горизонтальное масштабирование потребует переезда на PostgreSQL.
- Один пользователь — один привязанный чат.
